# results/

Raw Perlmutter outputs and the organized copy of them. **Start with [`MANIFEST.md`](MANIFEST.md)**: one row per run with its job, nodes, world size, seed,
metrics and a validity label (valid / smoke test / partial / suspect collision).

## Layout

| path | what |
|---|---|
| `MANIFEST.md` | generated by `tools/organize_results.py`; computed from the files, not from run names |
| `organized/job<ID>_<N>node_<interactive\|batch>/<run>/` | copies of `config.json`, `metrics.jsonl`, `step_times.csv` (+ `_provenance.json`: source copy, md5s, notes) for each run, plus that job's `gpu_*.csv` and batch `.out` log |
| `organized/_suspect_collision/` | runs whose files look written by more than one run; kept as-is, **not** merged or attributed |
| `organized/_unattributed/` | runs with no `runs.jsonl` record (e.g. still running when copied), so the job is unknown from the files |
| `runs.jsonl`, `runs/`, `gpu/`, `RESULTS.md` | the first-session results added in PR #4 (job 60622124 only); `RESULTS.md` is built by `tools/make_results.py` |
| `../powersgd_results/` | raw scp copies (`results/`, `results_2node/`, `logs/`), untouched and git-ignored. `organized/` is copies of these |

Rebuild after re-copying (put new copies such as `results_batch/` and `logs_batch/` inside the raw folder):

```bash
python tools/organize_results.py --raw powersgd_results --out results
```

## Caveats (read before using any number)

- **Single seed per configuration** (seed 1). The only repeats are `rerun_ddp_s1` and `rerun_r4_s1`; MANIFEST shows how far they land from the originals.
- **Do not use final val loss as the headline.** DDP overfits (best val loss around step 500 to 750, then rising while train loss keeps falling); the PowerSGD
  runs are still improving at the last step. Use best val loss and its step (both in MANIFEST, computed from `metrics.jsonl`).
- **2-node runs use global batch 512 (world size 8) vs 256 on 1 node**, so absolute losses are not comparable with the 1-node runs.
  The learning rate is **not** scaled: `lr_eff` is 0.001 at both world sizes in the `start` lines (the trainer only scales lr for ResNet-18). The raw `config.json`
  has `lr: null`; the used value is in the `start` line.
- **Different GPU models:** the 2-node interactive runs report `A100-SXM4-40GB`; every 1-node run reports `A100-SXM4-80GB`. Step times across those are not a pure
  node-count comparison.
- **Same run names, two jobs:** `gpt_ddp_2node`, `gpt_r2_2node`, `gpt_r4_2node` were used by the interactive job 60627319 and the 2-node sbatch 60623329, writing to the same folders.
  In the current copy `gpt_ddp_2node` already holds two complete runs in one `metrics.jsonl` (flagged `suspect collision`). Each block is attributed in MANIFEST by exact match:
  block 1 to the interactive job 60627319 (final val equals its `runs.jsonl` record), block 2 to the batch job 60623329 (all 8 eval values identical to its `.out` log).
  `step_times.csv` cannot be split. After the batch jobs finish, `gpt_r2_2node` and `gpt_r4_2node` may be doubled the same way.
- `comm_bytes_per_step` is the logical payload given to `dist.all_reduce` per rank, not wire bytes. `GPU-h` is wall-clock x GPUs for the run.
- `config.json` `rank` is a CLI default (2) for DDP runs, not a PowerSGD rank.
- GPU CSVs for the batch jobs were copied mid-run (partial). No GPU CSV exists for the 2-node interactive job 60627319.

## Not run

ResNet-18/CIFAR-10 with `train_ddp.py`, FP8 (A100 has no native FP8), tensor parallelism, LSTM in `train_ddp.py`. No files exist for any of these.
